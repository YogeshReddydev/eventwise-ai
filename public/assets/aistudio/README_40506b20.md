# EventWise AI

**A budget-aware, GenAI-powered event planning assistant with a Plan Recovery Engine.**

EventWise AI helps people plan weddings, birthdays, and community events. It builds a starter budget, creates a date-aware task list, tracks vendor outreach, and suggests how to adapt when costs or guest counts change. The initial demo is configured for a wedding with a ₹1,00,000 budget, 150 guests, and 60 days to go.

> All starter costs are illustrative estimates, not vendor quotations. The app does not verify or book vendors. Recovery plans are proposals and require user approval.

## Challenge vertical and persona

- **Vertical:** Event planning (wedding, birthday, community event).
- **Primary persona:** Someone organizing a wedding on a defined budget who needs clear next steps and help handling changes.
- **Core problem:** Event plans often live in scattered notes. Budget changes and vendor quote increases can cause overruns and missed deadlines.
- **Approach:** Combine deterministic calculations for budgets and recovery with Gemini for open-ended, personalized suggestions. The model does not control arithmetic or silently approve plan changes.

## Features

- Event brief: event type, total budget, guest count, and days remaining.
- Budget breakdown with editable category allocations.
- Budget per guest and a transparent contingency category.
- Date-aware timeline with priorities and interactive completion tracking.
- Vendor checklist for vendor name, quote, and booking status.
- Plan Recovery Engine for budget changes, vendor quote increases, and guest-count changes.
- Proposed changes require explicit acceptance; the original plan is not mutated by the recovery calculation.
- Optional Gemini API assistant with safe local demo fallback when no key is configured or the service is unavailable.
- Input validation, accessible labels, keyboard focus styles, and automated tests.

## Architecture

```text
Browser (HTML/CSS/JavaScript)
        |
        | JSON requests
        v
Flask API (app.py)
   |              |
   |              +--> Optional Gemini API (personalized suggestions)
   |
   +--> Deterministic planner and Plan Recovery Engine
```

Budget arithmetic and change proposals run in Python. Gemini is used for open-ended ideas and explanations, not as the source of truth for calculations. This small dependency footprint helps keep the repository below the challenge's 10 MB limit.

## Run locally

Requires Python 3.10 or newer.

1. Clone the public repository and enter the project directory.
2. Create and activate a virtual environment.

   **Windows PowerShell**
   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   pip install -r requirements.txt
   ```

   **macOS/Linux**
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. Start the app:
   ```bash
   python app.py
   ```
4. Open http://127.0.0.1:5000 in your browser.

The core planner and recovery tools work without an API key.

## Enable Gemini

1. Create an API key in Google AI Studio.
2. Set it in your local environment. Do not paste it into source files or commit it.

   **Windows PowerShell**
   ```powershell
   $env:GEMINI_API_KEY="your-key"
   $env:GEMINI_MODEL="gemini-2.5-flash"
   python app.py
   ```

   **macOS/Linux**
   ```bash
   export GEMINI_API_KEY="your-key"
   export GEMINI_MODEL="gemini-2.5-flash"
   python app.py
   ```

The app sends the event plan and question to Gemini. Avoid putting sensitive personal information into prompts. If the API is unavailable, the app displays a fallback message and local planning still works.

## Plan Recovery Engine

### Supported scenarios

- **Budget changes:** Rebalances allocations toward a new total, reducing flexible categories before protected essentials where possible.
- **Vendor quote increase:** Uses contingency first, then proposes reductions to flexible categories. It reports a shortfall if the budget cannot cover the full increase.
- **Guest-count changes:** Updates the guest count and estimates the possible catering impact using the current catering allocation per guest.

Every recovery response includes notes and `requires_user_approval: true`. A quote increase can make the displayed category allocations temporarily differ from the original budget total because the higher vendor commitment is represented explicitly. The user should review the proposal before accepting it.

## API endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/plan` | Create a starter plan. Optional query parameters: `budget`, `guests`, `days`, `event_type`. |
| `POST` | `/api/recover` | Propose a recovery plan. JSON fields: `plan`, `change_type`, `value`, and optional `category`. |
| `POST` | `/api/assistant` | Ask for event suggestions. JSON fields: `prompt` and optional `plan`. |

Example recovery request:

```json
{
  "plan": { "budget": 100000, "guests": 150 },
  "change_type": "vendor_increase",
  "value": 12000,
  "category": "Catering"
}
```

In real usage, send the complete plan object returned by `/api/plan`, not the abbreviated example above.

## Assumptions and limitations

- Default category amounts are a sample allocation, not location-specific market research.
- The sample plan contains a contingency allocation; actual costs will vary by city, season, date, and requirements.
- Vendor availability, ratings, identities, and prices are not fetched or verified.
- Tasks use dates relative to the day the plan is generated; users should adjust them to their event details.
- The first version is a single-user prototype. It does not provide authentication, cloud persistence, payments, or multi-user collaboration.
- API availability, quota, model names, and pricing can change. Configure a supported Gemini model for your account.
- Never commit `.env`, API keys, customer details, or other secrets.

## Security and responsible use

- API keys are read from environment variables and must remain private.
- Prompts are limited to 2,000 characters.
- Inputs for budgets, guests, and days are validated before planning.
- Gemini output is displayed as advice and is not executed as code or used to approve purchases.
- Verify all quotations, contracts, venue details, and vendor claims independently.
